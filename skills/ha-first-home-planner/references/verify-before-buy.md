# 買之前要查的事

原則：**你（模型）當下查，附連結和查證日期**；查不到寫「未查證」。不要用訓練資料裡的印象回答
「這個型號 HA 支不支援」——同名不同版、韌體改版、整合改寫都很常見。

## §1 每一項「必買」都要查

| 查什麼 | 去哪查 | 看到什麼算過關 |
|---|---|---|
| HA 有沒有整合、走本地還是雲端 | HA 整合頁 `https://www.home-assistant.io/integrations/<名稱>/`，看頁首的 IoT class 與品質分級（Bronze／Silver／Gold／Platinum） | `Local Push`／`Local Polling` 最好；`Cloud *` 要寫進「斷網還剩什麼」那格 |
| 第三方整合（HACS） | GitHub repo 的 `manifest.json` → `iot_class`；issue 區搜 `unavailable`、`offline`、`list index out of range`；最近一次 release 日期 | 近一年有維護、維護者有回 issue；HA 官方不審查第三方整合 |
| Zigbee 裝置認不認得 | Zigbee2MQTT 支援清單 `https://www.zigbee2mqtt.io/supported-devices/`；ZHA 參考 `https://zigbee.blakadder.com/` | **型號（model ID）完全一致**；只寫「Zigbee 3.0 相容」不算 |
| Matter 是不是真的 | 包裝與產品頁的 Matter 標誌；CSA 認證資料庫 `https://csa-iot.org/csa-iot_products/` | 有認證；確認是 Matter over Wi-Fi 還是 over Thread；有沒有「要先註冊廠商帳號」 |
| Thread 有沒有邊界路由器 | 使用者家裡既有的智慧音箱、電視盒規格；**HA 能不能共用它的 Thread 網路**（HA 的 Thread 文件、手機 Companion app 有沒有同步 Thread 憑證的功能） | 有而且 HA 能用；家裡有 Apple／Google 的邊界路由器不代表 HA 自動能用，查不到就寫未查證 |
| 智慧插座插高功率電器（電暖器、熱水壺、除濕機） | 插座的額定電流／功率 vs 電器的標示功率；斷電恢復後的預設狀態（產品頁或 Zigbee2MQTT 裝置頁的 power-on behavior） | 額定留餘裕：台灣 110V 下電流＝瓦數÷110，1500W 電暖器約 13.6A，**10A 的插座帶不動**；恢復後狀態符合需求（除濕機要「恢復通電」，電暖器通常要「保持關閉」） |
| 停電通知 | UPS 有沒有 USB／網路狀態輸出、HA 有沒有本地整合讀得到（例如 NUT） | 主機＋數據機＋路由器都在 UPS 上 |
| 主機規格夠不夠 | 要跑的東西的官方硬體需求（Frigate、Whisper 等） | 留餘裕；記憶體別抓剛好 |

## §2 台灣在地化查核

| 項目 | 要查什麼 | 備註 |
|---|---|---|
| 電壓與插頭 | 台灣 110V／60Hz，插頭 A／B 型。陸版、歐版設備（220–240V）不能直接插 | 智慧插座、除濕機、掃地機座充都要看；變壓器不是長久之計 |
| 無線設備合法性 | 台灣販售的無線設備要有 **NCC 審驗**標籤 | 海外代購（淘寶集運、亞馬遜）的設備可能沒有；請使用者自行判斷，模型不要替他下法律結論 |
| 插電設備安全 | 經濟部標準檢驗局的**商品安全標章**（插電類） | 便宜白牌插座、延長線特別要看 |
| 米家設備 | 是台灣版還是陸版？App 選的伺服器區域？逐台看 HA 有哪條路接：HA 內建的 `xiaomi_ble`（藍牙感應器，Local Push）、`xiaomi_miio`（部分 Wi-Fi 家電，Local Polling），或小米官方 `ha_xiaomi_home` | 截至 2026-10：**藍牙溫濕度計這類常能走 `xiaomi_ble` 本地讀**（加密款要 bindkey，整合可用小米帳號取一次）；`xiaomi_miio` 支援的 Wi-Fi 家電本地輪詢（要 token，同樣取一次）。官方 `ha_xiaomi_home` 的雲端六區沒有台灣，穩定本地控制要「中樞網關」（官方寫只在中國大陸可用），藍牙 Mesh／Zigbee 子設備靠網關。結論：**逐台查，不要整批當雲端**；能本地的接，不能的當旁觀者。另外：設備本身仍會連小米雲（陸版連陸區）——使用者不想資料去中國，要先確認本地路徑能用，再考慮在路由器擋它出網（§3 末段的驗法） |
| 涂鴉／Smart Life 白牌 | 是 Wi-Fi 還是 Zigbee？Wi-Fi 款多半走涂鴉雲；Zigbee 款可以直接配 HA 的接收器，不用涂鴉網關 | 白牌 Zigbee 要查 Zigbee2MQTT 清單；涂鴉雲整合斷網就停 |
| 台灣品牌家電（除濕機、冷氣、冰箱） | 有沒有 HA 官方整合？沒有就是 HACS 或紅外線遙控（IR blaster） | 這類家電只當「旁觀者」，不當其他自動化的前提（principles.md §3） |
| 通知送不送得到、叫不叫得醒 | **LINE Notify 已於 2025-03-31 結束服務**（LINE 官方公告），網路上舊教學的「HA 發 LINE Notify」都不能用了；替代是 HA 手機 app 推播，或 LINE Messaging API（要設定、有免費額度上限）。半夜要叫醒人：iPhone 可用 critical notification 穿過勿擾，Android 要另設通知頻道（HA Companion 文件） | 收件人實際收到過一次測試通知（用行動網路，不是家裡 Wi-Fi） |
| 中文語音 | 查 `https://github.com/OHF-Voice/intents/blob/main/languages.yaml` 的 zh-TW 段：speech-to-text 與 text-to-speech 各有哪些標 true；喚醒詞有沒有中文 | 截至 2026-10：zh-TW 只有 cloud 標 true，本地 Whisper／Speech-to-Phrase／Piper 皆 false；接回 Siri／Google 通常比較省事 |
| 台電電價、智慧電表 | 現行電價表（每次調價都要改）；HA 有沒有官方台電整合 | 截至 2026-09 無成熟官方整合 |
| 租屋 | 合約有沒有限制改裝；退租要不要恢復原狀 | 黏貼型、插座型、電池型為主 |
| 退貨 | 通路的退貨期限與條件 | Zigbee 型號不相容是最常見退貨理由，先買一顆試 |

## §3 「這台能不能斷網」矩陣（使用者已經有一堆雲端設備時用）

一台一行。先填「本地路徑」——填不出來的，就是要去查 HA 整合設定的那一台。

| 裝置 | 本地路徑（HA 從哪條路跟它講話） | 斷網損失 | 結論 | 重評條件 |
|---|---|---|---|---|
| 例：智慧插座（Zigbee） | 有：Zigbee 接收器 | 無 | 能斷 | — |
| 例：閘道器＋窗簾 | 有：社群本地整合 | 廠商 app 顯示離線 | 能斷 | — |
| 例：雲端掃地機 | 無：雲端帳號型 | 地圖、app 全斷；部分機型斷網還會鎖本地 API | 放棄（接受它連雲） | 換支援 Matter 或本地韌體的型號 |
| 例：品牌除濕機 | 無：品牌雲 | 遠端控制與整合全斷 | 放棄，只當旁觀者 | 品牌開放本地 API |

「連著雲」不等於「靠雲運作」：看路由器連線表只能知道前者，要知道後者得看 HA 是從哪個整合、哪條路跟它講話。
真的要切外網，切完驗四件事：舊連線斷了、新連線建不起來、本地路徑活著、功能實際動一次。

## §4 要接 HACS 第三方整合時

接之前：
- [ ] 官方整合有沒有、品質分級是哪一級
- [ ] `iot_class` 是 `local_*` 還是 `cloud_*`
- [ ] issue 區最近一年「unavailable」類問題有幾筆、維護者多久回
- [ ] 同一個帳號底下幾台裝置、有沒有常離線的那台（爆炸半徑）
- [ ] 這個整合掛掉，會停幾條自動化

接之後：
- [ ] 記下能用的版本號；更新提示不要順手按，有理由才升級
- [ ] 升級前先備份

## §5 查證結果的寫法

在購物清單的「買之前要查的事」裡，每一條寫成：

```
- [x] Zigbee 溫濕度感應器 ○○ 型號在 Zigbee2MQTT 支援清單上（<連結>，2026-10-14 查）
- [ ] 台灣通路價格：未查證（請使用者自行比價）
```

沒查的就留空格，不准寫成已查。
