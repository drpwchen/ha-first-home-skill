# 情境 3：常出國單身、剛交屋、想要中文語音

## 人物設定

使用者開場說：「I travel a lot for work. 想要出國的時候可以知道家裡狀況，還有用中文語音控制家裡，要買 HA Voice 嗎？」

（模擬人物。以下是對任何訪談題目的真實答案；照 skill 問到哪一題，她就照這裡回答；skill 沒叫你問的就當作不知道）

- 新竹自有電梯大樓，18 坪 2 房，剛交屋、裝潢中，可以改線路、牆壁開關都還沒買

### 第 3 步：生活小事翻成物理狀態

1. 當**地上有水**（洗衣機、水槽下、浴室）的時候，手機要響、她在國外會知道；朋友是第二聯絡人（待她決定）。
2. 當**市電斷了**的時候，UPS 撐住主機與網路、送出「停電了」；整個家都斷線時，**家以外的心跳接收器**發現「HA 沒回報」並通知她。
3. 當**貓房間溫度超過門檻**的時候，手機要響；之後要能遠端開冷氣（連到第 3 件事）。
4. 當**她說「關客廳燈／開窗簾」**的時候，燈與窗簾要動——這是指令，不是物理狀態監測；翻得出動作但本身沒有監測價值 → 放「可等」，等開關與窗簾馬達裝好。
5. 當**她在回家路上**（手動觸發或手機定位）的時候，冷氣要開——依賴冷氣機型，放「可等」。

**先回答你的問題：HA Voice 現在不用買。**

- 你已經有 HomePod mini。把 HA 裡的燈、窗簾、冷氣用 HA 的 **HomeKit Bridge** 接回 Apple 家庭 App，就能直接用 Siri 講中文控制。HomeKit Bridge 是 `Local Push`，HomePod 與 HomePod mini 也是官方測試過的家庭中樞（[HA HomeKit Bridge 整合頁](https://www.home-assistant.io/integrations/homekit/)，2026-10-14 查）。
- HA 自己的語音在繁中這一層還沒到位：官方語言表 zh-TW 的語音轉文字只有 `cloud: true`，本地 `whisper`／`speech-to-phrase` 都是 `false`；文字轉語音本地 `piper: false`（[OHF-Voice/intents languages.yaml](https://github.com/OHF-Voice/intents/blob/main/languages.yaml)，2026-10-14 查）。所以「中文＋HA Voice」實際上等於「語音送 Home Assistant Cloud 辨識」，而且還得自己實測辨識品質。
- 中文喚醒詞：未查證（這次查的語言表沒有喚醒詞資料）。
- 你真正的第一名問題是「不在家時知道出事」，這件事不需要語音。語音放「可等」。

## 第一週要做的事

1. **心跳接收器在出國前接好並實測一次**：拔掉主機電源，看幾分鐘後手機有沒有收到「HA 沒回報」。這是你出國時唯一能發現「整個家斷線」的路。
2. **Zigbee `availability` 第一天打開**：不然沒電的水浸感測器會一直顯示「乾」。
3. **備份**：每日自動全備份、保留一週以上，一份在主機以外（HA Cloud 的異地備份或你自己的 NAS）。
4. **命名規則從第一台開始**：房間_用途（例如 `bathroom_leak`、`catroom_temp`），改名會悄悄弄壞引用它的地方。
5. **實際驗收一次漏水通知**：用濕布碰水浸感測器，確認手機在 4G（非家裡 Wi-Fi）下真的響——驗的是「事情有沒有發生」，不是 HA 說「已送出」。

## 這份規劃沒有幫你決定的事

- **漏水時誰去處理**：要不要把漏水與「整個家斷線」的通知也送給有鑰匙的朋友？朋友願不願意？這要你跟他談。
- **電動總水閥**：漏水時自動關總水閥牽涉水路改管，要找水電現場判斷；這份清單只做到「通知你」。
- **貓房過熱時的處置**：冷氣怎麼遠端開、冷氣也壞了怎麼辦（朋友？），以及溫度門檻設多少——這是你對貓的判斷。
- **家裡網路架構**：訪談沒問到你的路由器／mesh 規劃；Wi-Fi 裝置變多時路由器是隱藏的第一期項目，攝影機要不要另切網段也要現場決定。
- **攝影機的確切位置與角度**：現場判斷。
- **門鎖、保全**：不在這份規劃裡；用原廠方案，HA 只讀狀態不控制。
- **市電接線**（智慧開關、UPS 擺放的插座迴路）：找合格電工。
