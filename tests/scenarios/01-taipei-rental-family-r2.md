# 情境 1（第二輪）：台北租屋小家庭

## 人物設定（照抄上面）

使用者開場說：「我想開始弄智慧家庭，聽說 Home Assistant 很強，要買什麼？」

- 台北市大樓公寓，租屋，25 坪 3 房，房東不准改線路、不准打牆，大概還會住 3 年
- 夫妻＋一個 4 歲小孩＋一隻貓。太太用 iPhone、不想學新 app；他自己 Android
- 想解決：1) 小孩房和衣櫃很潮濕、冬天棉被有霉味，已有一台除濕機（品牌 app 可控）2) 半夜起來上廁所、走廊太暗會踢到東西 3) 出門上班後常懷疑電暖器／電熱水壺沒關。（被問先後時：他說電暖器最怕，其次潮濕）
- 家裡已有：小米米家（台灣買的）掃地機、2 個 Wi-Fi 智慧插座（涂鴉 Smart Life 白牌，蝦皮買的）、Google Nest Mini 一台
- 網路：中華電信附的路由器放客廳電視櫃；不能拉線；沒有 NAS，有一台舊筆電
- 預算：第一期 8,000 元內，之後一年再 1 萬
- 隱私：不要室內攝影機；不太在意資料出國但不要中國；語音上雲沒差
- 一年出國 1–2 次各一週，岳母會來餵貓
- 他會用 Docker（後端工程師），願意寫 YAML，不想拆機焊接；會用 Claude Code

### 每件事翻成「盯什麼物理狀態」

| # | 一句話 |
|---|---|
| 1 | 當**電暖器（或熱水壺）那顆插座的功率 > 門檻**、而且**你的手機離開家**的時候，**你的手機要跳一則帶「關掉」按鈕的通知**，你會知道；你按了就斷電。（不做「沒人在家就自動斷」：太太和小孩白天可能在家，而太太沒有 HA app，系統判斷不了她在不在——推測） |
| 2 | 當**小孩房或衣櫃的相對濕度連續一段時間 > 門檻**的時候，**除濕機要開**（或先只是記錄），**你**會知道。第一期先量，執行端等數據 |
| 3 | 當**走廊在夜裡有人經過**的時候，**燈要亮**，**起來上廁所的人**當場就會知道它壞了（笨方法：不連網的感應夜燈） |

## 買之前要查的事

> HA 官方論壇因為 AI 的答案「wrong in subtle ways」禁止貼 AI 生成的回答（[2023 公告](https://www.home-assistant.io/blog/2023/01/23/help-others-leave-ai-at-the-dor/)）。這份規劃也是 AI 做的，下面每一條請回原廠／HA 頁面核對過再下單。

**主機（舊筆電）**
- [ ] 筆電是 x86-64、能 UEFI 開機、有網路孔（或 USB 網卡），記憶體 ≥ 4 GB——對照 HA 官方 generic x86-64 安裝頁的需求（未查證）
- [ ] 硬碟裡的東西先備份走（HA OS 會整顆清掉）
- [ ] BIOS 能不能設「通電自動開機」、蓋上螢幕不休眠（未查證，看筆電型號）

## 第一週要做的事

1. **備份**：HA 設定自動每日備份、保留一週以上，另存一份不在筆電上（Google Drive 或你的電腦）。筆電是消耗品，設定才是資產。
2. **Zigbee availability 打開**（ZHA 或 Zigbee2MQTT 都有）：插座失聯要真的變成「不可用」並通知你，不然它會一直顯示最後的功率值。
3. **心跳接收器在第十台裝置之前接好**：HA 每幾分鐘打一次家外的服務，斷了由外面通知你。拔一次網路線驗收。
4. **命名規則從第一台開始**：`房間_用途`，例如 `客廳_電暖器插座`、`廚房_熱水壺插座`。改名會悄悄弄壞引用它的自動化。
5. **實體開關保留**：電暖器、熱水壺本體的開關照舊能用；智慧插座本體按鈕也能手動切。跟太太講一句「插座上那顆按鈕按一下就恢復」，HA 整個掛掉時她不會被困住。

> 裝好之後，寫自動化（「電暖器功率 > 門檻且你離家 → 推播帶按鈕」）交給 HA 官方 skills／ha-mcp 配 Claude Code 做；觸發條件記得寫 `from:`，避免插座重新上線被當成一次觸發。

## 這份規劃沒有幫你決定的事

- **出國那兩週誰去現場**：通知只送你；你在國外收到「電暖器在吃電」或「家裡斷線」時，誰去開門處理？岳母只餵貓（推測），要不要請她當第二收件人、她手機收不收得到——要你跟她講好。
- **太太要不要參與**：她不裝 app 的前提下，HomeKit Bridge 是唯一不用學新 app 的路；要不要做，先問她。
- **白天家裡有沒有人**：如果太太和小孩白天常在家，「你離家＋電暖器在跑」就會常常誤報；誤報多了你會開始忽略它。門檻與時段要跑一兩週再調。
- **電暖器本身的安全**：傾倒斷電、過熱保護、離床邊與窗簾的距離——這是電器本身和擺放的問題，智慧插座只能「知道它在吃電」，保證不了不起火。
- **網路分段、路由器要不要換**：第一期裝置少，中華電信的路由器應該撐得住；第二期 Wi-Fi 裝置變多再評估。
- **夜燈位置與數量**：要回現場看動線。

## 執行者筆記

1. **「視情況」題的時序矛盾**：interview.md 的夜間動線題放在第 1 輪「視情況」，但它的觸發條件（要解決夜間問題）是第 1 輪第 1 題的答案；如果同一輪合併成一句問，就問不到。我移到第 2 輪問，第 2 輪剛好 5 題沒超限。建議題庫註明「條件來自同一輪答案時，下一輪問」。
2. **「必買只放第 1 名問題」跟「預算明明有餘」打架**：溫濕度感應器很便宜、第一期預算塞得下，但規則說第 2、3 名問題放可等。我照規則放可等，但條件寫成「第 2–4 週就可以買」，看起來有點彆扭。skill 沒說預算有餘時能不能把第 2 名提前。另外「非智慧的笨方法可以放必買」讓我把第 3 名的感應夜燈放進必買，第 2 名卻在可等——排序跟使用者的先後顛倒了，skill 允許但讀起來怪。
3. **「誰會知道」與「沒人在家才斷電」**：太太不裝 HA app，HA 判斷不了她在不在家，所以「全家離開就自動斷電」做不出來，只能退成「你離家就問你」。skill 第 3 步沒提到「不裝 app 的家人會讓在家判斷失效」，這是我自己推的（principles 也明說在家判斷不規劃細節）。
4. **主機選擇的條件互相拉扯**：「舊電腦只在維護者住同一個家時試」→ 成立；但「常出國」那條又要求監控與心跳提前。一年 1–2 次算不算「常出國」skill 沒定義；我判斷算半個，所以把遠端存取（本來就因上班需要）和心跳放必買，UPS 放可等。舊筆電長年插電的電池風險 skill 沒提，我自己加的。
5. **遠端存取寫法踩到「不寫型號」**：Tailscale、Home Assistant Link 都是具名服務。skill 在遠端存取那段自己就點名 Nabu Casa，我視同服務類可以寫名字，但硬體不寫型號。查證連結裡出現了型號（SONOFF、akubela）——那是查證來源，不是推薦，但使用者可能會讀成推薦，skill 沒說怎麼處理。
6. **輸出格式沒有「既有設備矩陣」的位置**：特殊情況要求已有雲端設備時用 §3 矩陣逐台分類，但〈輸出格式〉沒有這一段。我放在〈你的需求〉底下，屬於自己判斷。
7. **台灣價格查不到**：6 次搜尋都沒拿到台灣通路的 Zigbee 類價格（WebSearch 是 US-only，台灣電商頁面很少被索引），預算檢核只能給海外參考＋推測。建議 skill 在預算檢核加一句「搜尋工具查不到台灣通路時，直接讓使用者比價、只給超支砍單順序」，或把「查不到」當成預期結果寫進去。
8. **高功率電器接智慧插座**：verify-before-buy §1 有「額定留餘裕」，但沒提 110V 下 10A 插座帶不動 1500W 電暖器這個台灣特有的算術陷阱，也沒提很多插座禁止接發熱電器。這是第 1 名問題的核心，我自己補了。查到的一份台灣代理規格書 10A 與 1800W 自相矛盾，順手寫進買前要查。
9. **「不要中國」對涂鴉／米家的判斷**：skill 只說「不連中國：米家／涂鴉類先查本地整合」，沒說涂鴉雲、米家雲對台灣帳號的資料落地在哪。我沒查（搜尋次數用完），標未查證；沒辦法給使用者肯定的結論。
10. **未查證項目**：HA OS x86 安裝需求、Zigbee2MQTT 協調器清單、Home Assistant Link 價格、Tailscale app 現況、Gemini for Home 台灣狀態、米家整合區域（沿用 skill 參考檔的 2026-10 說法，未重查）。本次實際查過的：HA Tuya 整合頁（Cloud Push）、Home Assistant Link 改名公告（無價格），以及四次價格搜尋（皆 2026-10-14）。
